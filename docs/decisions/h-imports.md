# Unit H import decisions

Imports use the existing `imports` and `import_chunks` base tables. The module migration adds upload timestamps, original headers, per-row checkpoints, skip reports, file deduplication and a domain DNS cache. Each processed row commits its contact changes, counter and checkpoint together. A run handles at most one uploaded chunk and yields when the shared outbound or time budget runs out.

The import states are `uploading`, `queued`, `processing`, `completed`, `canceled`, `stalled`, and `failed`. An upload gets a durable sweep job at creation. Upload activity moves its expiry; the sweep ends uploads with no new chunk for one hour. Cancellation preserves completed rows. Processing failures retry through the common queue; the eighth failure marks the report failed and creates a notification.

Every contact insert calls `contacts.subscribe`. Imported opt-outs first create an unconfirmed contact when limits permit, then suppress it in the same transaction. They never become subscribed. Their historical signup time is retained as `createdAt`; `subscribedAt` remains null because the contact has never subscribed here. When limits prevent even an unconfirmed row, the suppression still persists. The `imported_unsubscribed`, `imported_cleaned`, `imported_bounced`, and `imported_complained` report reasons count these safe inactive outcomes among skipped rows. `activeOnly` avoids creating inactive contacts but still honors their suppressions. Existing duplicates are skipped, so `updated` remains zero.

Imports always use `asserted` or `pending` consent. The `confirmed` consent path is reserved for a contact's own action. This preserves deleted-contact tombstones and newsletter suppressions when contacts confirmed elsewhere are imported.

The browser uses Papa Parse in a dedicated module worker. It previews five records and pauses until each upload is acknowledged. Chunks contain at most 500 rows and shrink for wide rows to remain below the HTTP body limit. A failed chunk retains its sequence and rows for retry. After a reload, reselecting the same file replays its chunks against the existing import; the server verifies their contents before treating them as duplicates. File metadata and the import id are saved locally, without contact data. The raw CSV stays in the browser until its parsed chunks are uploaded.

MX results, including missing MX, are cached for 24 hours. Resolver failures throw and retry instead of claiming a domain has no MX. Each global suppression RPC and uncached DNS lookup consumes the shared budget. The bundled disposable-domain list has 10,234 entries and includes its CC0 license.

The skipped CSV includes all original columns and uses `contacts.csvCell` for every cell, including headers, reasons and suggestions. The authenticated GET download uses the registered `imports.skipped` action name so the edge can route it. Authorization runs before streaming and before each later page.

Shared-file edits are limited to:

- `package.json` and `package-lock.json`: add the architecture-approved `papaparse` package and its TypeScript declarations.
- `server/account/contacts/index.ts`: export `ensureTags`, `isDeleted`, and `validateFields`, keeping taxonomy writes, tombstone hashing and typed-field validation inside the contacts module. Imports validate fields and check limits before creating tags because nested transactions share the outer transaction.
- `server/account/notifications/index.ts`: export `notify`, which inserts an in-app notification. Imports use it for completion and terminal failure. The notification unit can keep this export when it replaces the existing registration stub.

No architecture file or base migration is edited. The additional import state, checkpoint tables and report conventions above extend the contract within this module. Platform export research and its limits are recorded in [the preset reference](../../server/account/imports/PRESETS.md). Beehiiv's exact current CSV headings remain unverified. Its public [create subscription export](https://developers.beehiiv.com/api-reference/exports/create) and [get subscription export](https://developers.beehiiv.com/api-reference/exports/show) API docs describe basic and full variants and a signed CSV download URL, but neither lists the columns. Candidate migration pages from Kit, Buttondown, and Ghost returned not-found pages; the candidate EmailOctopus host did not resolve. No public sample export was available from these sources. The beehiiv fixture remains a representative layout, not a verified current export. Detection matches an email header plus any recognized beehiiv signal, ignoring case, punctuation, order, and additional columns. Missing signals fall back to generic detection. The mapping screen always lets the operator choose columns before upload. Other platform help pages often describe configurable fields rather than literal headers, so the editable mapping remains necessary.

Verification commands are `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npm run smoke`, and `npm run smoke -- --dev`. `npm test` includes the 100 MB CSV parser check, which completed in under a second locally. `npm run test:slow` explicitly selects `server/test/*.slow.ts` and checks 100,000 persisted contacts. Neither suite uses skipped tests. The parser test executes the bundled worker with a file-reader substitute; it does not claim a visual browser check.

After merging the team unit, import mutations remain admin actions. Members can list imports, view reports, and download skipped rows. The UI exposes reports to members and keeps upload and cancel controls for admins. The per-module permission matrix and import behavior tests cover these roles. A sending integration test imports subscribed and unsubscribed CSV rows, sends a campaign to all contacts, and checks one email per subscriber and none per opt-out in both hosting modes.
